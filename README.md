# Steel Surface Defect Classification — Reproducible Handoff

Transfer-learning image classifier for the NEU-CLS steel-surface defect dataset (6 defect
types), with a safety-critical one-vs-rest threshold analysis on the `crazing` class. See
`vision_evaluation_report.md` for the full write-up and `decision_log.md` for run-specific
answers to the mandatory review questions.

## Repository layout
```
src/
  extract_features.py   # downloads nothing; reads local image manifest, runs frozen
                         # pretrained backbone, writes cached embeddings + augmented copies
  train.py               # trains majority-class baseline + classifier head on embeddings
  evaluate.py             # final test-set metrics, threshold sweep, false-negative extraction
data/
  split_manifest.csv     # reproducible train/val/test split (seed=42)
  classes.json            # class index ↔ name mapping
  *_features.npy / *_labels.npy / *_meta.csv   # cached embeddings per split (generated)
artifacts/
  classifier_head.keras           # trained model weights (head only; backbone is re-downloaded)
  baseline_results.json
  training_curve.csv              # per-epoch val loss/accuracy/macro-F1
  training_config.json
  test_metrics.json
  threshold_table.csv
  false_negatives_raw.csv
  qualitative_panel.png
  class_distribution.png
  sample_images_per_class.png
deliverables/
  dataset_notes.md, label_format_notes.md, class_distribution.md, split_notes.md,
  training_config.md, augmentation_notes.md, threshold_comparison.md,
  false_negative_analysis.md, qualitative_predictions.md, decision_log.md,
  vision_evaluation_report.md, metric_results.csv
```

## Data
The raw NEU-CLS images are **not** vendored into this repo (1,800 small JPGs). Retrieve them
from the public mirror used for this project:
```bash
git clone --depth 1 \
  https://github.com/siddhartamukherjee/NEU-DET-Steel-Surface-Defect-Detection.git \
  /path/to/NEU-DET-Steel-Surface-Defect-Detection
```
Then point `src/extract_features.py`'s pooling step at that checkout's `IMAGES/` and
`Validation_Images/` folders (the exact pooling + de-duplication + stratified-split logic used
to build `data/split_manifest.csv` is documented step-by-step in `split_notes.md` and
`dataset_notes.md`; re-run it with `random_state=42` to reproduce the manifest exactly).

The pretrained backbone weights are fetched automatically the first time you run
`extract_features.py`, from a public GitHub release (no API key / account needed):
```
https://github.com/fchollet/deep-learning-models/releases/download/v0.6/mobilenet_5_0_128_tf_no_top.h5
```

## Run (top to bottom)
```bash
# 1. Build the split manifest (see split_notes.md for the exact pooling/dedup/split code)
# 2. Extract frozen-backbone embeddings (train gets 2 extra augmented copies per image)
python3 src/extract_features.py

# 3. Train baseline + classifier head (checkpoints on best validation macro-F1)
python3 src/train.py

# 4. Final test-set evaluation: metrics, confusion matrix, threshold sweep, false negatives
python3 src/evaluate.py
```
All three scripts are deterministic given the same manifest and `random_state=42` / `seed=42`
settings already hard-coded in each file. Total runtime on a single CPU core, no GPU: under
two minutes.

## Reproducing the qualitative panel
The panel in `artifacts/qualitative_panel.png` (false negatives, hardest/easiest correct
predictions, crazing true positives) is generated by a short inline script that loads
`artifacts/classifier_head.keras`, re-scores the test embeddings, and pulls the corresponding
source images via `data/split_manifest.csv` — see the panel-generation snippet referenced in
`qualitative_predictions.md` for the exact selection logic (5 misclassifications + 2
lowest-confidence correct + 2 highest-confidence correct + 2 crazing true positives).

## Key results at a glance
- Baseline (majority class): 16.7% accuracy / 0.048 macro-F1
- Model: **98.15% accuracy / 0.981 macro-F1** on held-out test set (270 images)
- Crazing (safety-critical class): 100% recall at default threshold, ROC-AUC = 1.000
- 5 real test errors, all in one visually-ambiguous class pair (inclusion ⇄ pitted_surface)

See `vision_evaluation_report.md` for full discussion, limitations, and recommended next steps.
